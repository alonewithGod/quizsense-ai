# 연구 기록 - 구조 개선 및 1차 평가

- 일자: 2026-09-18
- 목적: 단일 파일 프로토타입을 테스트·평가 가능한 구조로 개선하고 중간보고서 근거를 확보한다.

## 1. 점검에서 확인한 문제

- UI, 오디오, 질문 판별, LLM 연동, 저장 로직이 한 파일에 결합되어 있었다.
- 자동 테스트와 정량 평가 입력·결과가 없었다.
- 영어 질문 표현 위주였고 중복 질문 억제 근거가 기록되지 않았다.
- README의 프로젝트 구조·라이선스 설명이 실제 저장소와 달랐다.
- 프로그램 시작과 동시에 마이크를 열어 사용자가 청취 상태를 제어하기 어려웠다.

## 2. 구현 내용

### 코어 모듈 분리

`quizsense` 패키지를 만들고 설정, 데이터 모델, 질문 탐지, LLM 응답 파싱, 세션 이력, 평가 로직을 분리했다. 장치가 없어도 핵심 로직을 테스트할 수 있다.

### 질문 탐지 개선

- 영어 의문사·조동사·강의 질문 표현과 한국어 질문 시작어·종결 표현을 함께 사용한다.
- 결과에 0~1 점수와 탐지 근거를 포함한다.
- 쿨다운과 문자열 유사도 기반 중복 억제를 분리해 억제 이유를 확인할 수 있게 했다.

### 기록과 평가

- Q&A 데이터 모델에 원문, 질문, 번역, 답변, 탐지 점수, STT·답변·전체 지연시간, 상태와 오류 필드를 정의했다.
- 세션 요약과 항목을 JSON 및 CSV로 저장하는 모듈을 추가했다.
- 라벨 CSV에서 혼동행렬, 정확도, 정밀도, 재현율, F1을 계산하는 CLI를 추가했다.

### 실행 제어

기존 UI에 `청취 시작`과 `중지` 버튼을 추가했다. 시작 중복을 막고 중지 시 마이크 스트림을 닫으며, 재시작할 때 작업 스레드를 새로 만든다.

## 3. 검증 결과

### 자동 테스트

- 명령: `python -m pytest`
- 결과: 10개 통과, 실패 0개
- 범위: 설정 검증, 한·영 질문 판별, 일반 문장 제외, 질문 추출, 쿨다운·중복 억제, 세션 요약·내보내기, LLM JSON 파싱

### 정적 검사

- `python -m ruff check quizsense tests`: 통과
- `python -m py_compile quizzesense_ai.py quizsense/*.py`: 통과
- `git diff --check`: 통과

### 질문 탐지 1차 평가

- 입력: `data/question_detection_eval.csv`
- 구성: 영어 20개, 한국어 20개; 질문 20개, 비질문 20개
- 결과: TP 20, TN 20, FP 0, FN 0
- 지표: 정확도 1.0000, 정밀도 1.0000, 재현율 1.0000, F1 1.0000

이 결과는 탐지 규칙을 검증하기 위해 직접 구성한 소규모 균형 데이터에 대한 결과다. 독립적인 실제 강의 데이터가 아니므로 실제 성능의 확정값으로 해석하지 않는다.

## 4. 미검증 사항

- 이 작업환경에는 실제 마이크 입력과 로컬 Ollama 모델이 준비되어 있지 않아 종단 실행을 검증하지 못했다.
- 실제 강의 음성의 STT 오류가 질문 탐지에 미치는 영향은 측정하지 않았다.
- 한국어 음성 전사는 실행 코드에서 아직 활성화하지 않았다.
- 교실 소음, 화자 거리, 마이크 차이에 따른 음성 구간 분리 성능은 미측정 상태다.
