1. 전체 시스템 구조 설계

## 4. 현재 코드에서 확인한 구현 상태

다음 내용은 실제 실행 결과가 아니라 `quizzesense_ai.py`의 정적 코드 검토를 통해 확인한 사항이다.

### 구현된 구성요소

- 마이크 입력 수집
  - `sounddevice.InputStream` 사용
  - 16 kHz, 모노 입력 설정
  - 큐를 이용해 오디오 블록 처리
- 음성 구간 분리
  - RMS 에너지 임계값을 이용한 간단한 음성/무음 판별
  - 일정 시간의 무음 이후 음성 구간 확정
- 실시간 음성 인식
  - `faster-whisper`의 `base` 모델 사용
  - CPU 및 `int8` 연산 설정
  - 현재 인식 언어는 영어(`en`)로 고정
- 문맥 유지
  - 최근 24초의 전사 결과를 롤링 버퍼에 보관
- 질문 탐지
  - 물음표, 영어 의문사·조동사, 강의 질문 표현 패턴을 이용한 규칙 기반 판별
  - 5초 쿨다운으로 중복 호출 억제
- AI 답변 생성
  - 로컬 Ollama API 사용
  - 기본 모델은 `llama3.1:8b`
  - 질문의 한국어 번역, 영어 답변, 한국어 답변을 한 번의 호출로 생성하도록 구성
- 사용자 인터페이스
  - Tkinter 기반 상단 고정 창
  - 감지 질문, 번역, 영어·한국어 답변, Q&A 이력 표시
- 결과 저장
  - 최근 Q&A 이력을 JSON 파일로 내보내는 기능 구현
- 기본 예외 처리
  - Ollama 호출 및 프로그램 시작 실패 시 오류 메시지 표시

### 신청서 계획과의 대응

| 신청서의 연구 단계 | 현재 상태 | 확인 근거 |
|---|---|---|
| 전체 시스템 구조 설계 | 코드상 구현 | 입력, STT, 질문 탐지, LLM, UI 모듈이 하나의 처리 흐름으로 연결됨 |
| STT 모듈 구현 | 코드상 구현 | faster-whisper 기반 전사 클래스 존재 |
| 질문 탐지 알고리즘 | 1차 규칙 기반 구현 | 물음표·의문 표현·시작 단어 규칙 사용 |
| LLM 응답 생성 | 코드상 구현 | 로컬 Ollama 호출 및 이중 언어 응답 처리 |
| UI 설계 및 구현 | 코드상 구현 | Tkinter 표시 창과 Q&A 이력 패널 존재 |
| 실험 및 결과 분석 | 미확인 | 정확도, 지연시간, 활용성 평가 자료 없음 |

## 5. 현재 한계와 확인이 필요한 사항

- 실제 강의 환경에서 프로그램이 정상 동작하는지 실행 검증 기록이 없다.
- 질문 탐지가 규칙 기반이므로 일반 설명문을 질문으로 잘못 감지하거나 간접 질문을 놓칠 수 있다.
- STT 언어가 영어로 고정되어 있어 한국어 강의에는 바로 적용하기 어렵다.
- RMS 임계값이 고정되어 있어 마이크, 교실 소음, 화자 거리 변화에 민감할 수 있다.
- STT 처리 시간과 Ollama 응답 시간을 측정하는 코드 및 결과가 없다.
- 질문 탐지 정확도를 계산할 정답 라벨 데이터셋과 평가 기준이 없다.
- 자동화된 테스트와 실제 실행 결과 캡처가 없다.
- README의 프로젝트 구조에는 `.gitignore`가 적혀 있으나 현재 저장소 루트에서는 해당 파일이 확인되지 않는다.
- README에는 라이선스 선택이 필요하다고 적혀 있으나 저장소에는 이미 MIT `LICENSE`가 존재하므로 설명 정리가 필요하다.
